1. Context Window Overflow
Your codebase + conversation can exceed the model's maximum context window.
: 76k / 128k used
When it overflows, the model silently drops your oldest code from context.
It then generates code that breaks the files it can no longer see.
→ Silent, invisible corruption

2. "Lost in the Middle" Effect LLMs pay most attention to the start and end of context. The middle gets foggy.
- Model's Attention →
HIGH
Your critical code files sitting in the middle of a huge context get ignored.

LLM lost the quality

because of which we need sub-agents.

What Are Subagents?
Specialized Al assistants that run in their own isolated context windows - doing heavy lifting in a separate space and handing
back only what matters.

with the help of sub-agent we can save our context and the session is longer lasted, and the quality of session is better.
when developing features one by one its better, compare to one session no agent it will exhaust in 7-8runs.

Why Use Subagents?
Four advantages. Six proven use cases.
ADVANTAGES:

Context Isolation (CORE ADVANTAGE) : whole new context window.
Modularity : each task different sub-agent(role based tasks)
Specialization : role based subagents.(tester, researcher,writer,coder all this with seperate tools assignment.)
Parallelism : each agent can work independantly parallel. (spin 3 agent with same role symaltaniously)


top use cases of subagents.
code base exploration: 
code review: coding agent cant be code reviewer because it is bias about the code he had written. because of tradeoff and decisions he took.
Testing: same idea above.
multi-stage pipelines: when working in a flow one module output is the input for the another module and so on then we use sub-agents to work independantly.
parallel independant tasks: 3 non-depending feature can be developed independantly and parallely.
security auditing: check for hack.

Types of Subagents
Built-in agents that Claude delegates to automatically, and custom agents you define for your own workflows.

BUIlT-IN SuBAgEnTS
Always available. Claude decides when to use them - no setup needed
1)explore: read only (when exploring code base)
2)plan: when we use plan mode for feature(spec document)
3)general-purpose: read-write both.

HOW SUBAGENTS GET TRIGGERED
You say something to Claude...
1)AUTOMATIC
    Claude recognizes the task needs a subagent and delegates on its own.
    "Add auth" → Claude spawns Explore first
2)EXPLICIT
    You tell Claude which subagent to use by name.
    "Use code-reviewer agent on auth/"
