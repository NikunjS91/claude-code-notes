Agent Loop:
Cycle 1: Model says "Read app.py"→ harness reads the file → sends contents back to model.
Cycle 2: Model says "Read database/schema.sql" → harness reads the file → sends contents back.
Cycle 3: Model says "Write the delete route to app.py" → harness writes the code to disk → confirms success.
Cycle 4: Model says "Run python -m pytest tests/" → harness runs pytest → sends test output back.
Cycle 5: Model sees all tests pass → responds with final text: "I've added the expense deletion route with proper parameterized SQL and a confirmation step. All tests pass."

Hooks:
Hooks are custom scripts written by the programmer that the harness automatically executes at specific events during a session's lifecycle.
Use-cases:

1. Auto-formatting & Linting -easy reading
2. Blocking dangerous shell commands
3. Protecting sensitive files
4. Notification
5. Telemetry
6. Generating summary

Black Formatter (github) post tool use.

Linting is about catching actual problems - bugs, bad practices, suspicious patterns - without running the code. A linter reads your source and flags things that are technically valid Python but are likely mistakes.

How Hooks work?

1. You ask Claude to "clean up the Spendly project"
2. Claude enters the agent loop and decides: "Bash: rm spendly. db"
3. The harness sees a Bash tool call and checks - is there a PreToolUse hook with a matcher that matches "Bash"? Yes
4. The harness runs your script, piping in JSON that contains the command rm spendly. db
5. Your script reads the JSON, sees rm targeting spendly. db, prints "Cannot delete the database file" to stderr, and exits with code 2
6. The harness reads exit code 2 - block. It does not run the command
7. The harness sends the error message "Cannot delete the database file" back to the model
8. The model reads the error, understands, and moves on to something else
9. The agent loop continues. Your database is safe
